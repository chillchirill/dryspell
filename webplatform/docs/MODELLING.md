# Numerical model and scientific limits

Implementation version: surface-grid-1.1.2; inference: sensor-ensemble-1.1.0. Contract 1.1.0. These are experimental numerical models, not calibrated operational wildfire forecasts.

## Surface propagation

The engine uses time-dependent shortest arrival paths on an sixteen-neighbour metric grid. For empirical fuel profiles it samples reusable directional weather/moisture rate curves at fixed five-second times plus every weather knot, integrates each piecewise-linear rate exactly, and solves each edge arrival by binary search and a stable quadratic root. This preserves changing weather without re-evaluating thousands of weather samples separately for every terrain edge. The published nonlinear fuel option and unusual excess shape combinations retain the fine-step reference integrator. A minimum heap propagates arrivals; there is no per-render growth or zero-delay chain. Constant-weather edges use the exact constant-rate solution. Water, built/non-burnable masks and unknown cells block local propagation. A diagonal is rejected if either orthogonal flank is non-burnable or unknown. Scheduled multiple ignitions compete by earliest arrival. Cells burn for the configured duration, then remain burned. Arrival-front travel is distinct from post-arrival cell lifetime: a centre-to-centre travel cutoff based on cell lifetime is intentionally not used, because it creates spurious grid-size-dependent extinction. Zero-rate moisture extinction still blocks the front. Long knight edges inspect both intervening cells and harmonically average their fuel rates; diagonal corner blocking remains enforced.

The input base rate is an explicitly configured metres-per-second rate. A geometric mean combines neighbouring rates. Wind-from degrees become east/north transport vectors; the empirical canopy reduction is 0.25 in woodland and 0.4 elsewhere. Directional wind and slope factors are bounded exponentials. Elevation differences determine edge grade; cell slope/aspect are inspector metadata. Humidity, temperature, precipitation and configured moisture modify the effective rate. These empirical coefficients are not extracted physical fuel-table parameters, and this is not a full Rothermel or FARSITE implementation. Published GR1/GR2/GR3 aggregate parameterizations are now available under explicit SB-GR1-equivalent-dead, SB-GR2-equivalent-dead and SB-GR3-equivalent-dead identifiers. These use fine fuel load, characteristic SAV, packing ratio and extinction moisture from Scott/Burgan printed pages 26–28, reviewed directly on 2026-11-14. Rothermel printed page 26 homogeneous no-wind equations compute their base rate; all fine fuel is explicitly approximated as dead. Heat content 8,000 Btu/lb, density 32 lb/ft³, total mineral .0555 and effective mineral .01 are declared assumptions. Empirical wind/slope modifiers remain. Complete live/dead dynamic curing, regional calibration and broader forest/shrub fuel tables remain incomplete; existing GR1-inspired/TL2-inspired/SH2-inspired sample mappings retain their explicitly empirical rates. Grass versus woodland ordering is input-dependent, not hardcoded as a universal scientific fact.

References read on 2026-11-14: [Rothermel (1972)](https://research.fs.usda.gov/treesearch/32533), [Scott and Burgan (2005)](https://research.fs.usda.gov/treesearch/9521). Their physical modelling motivation does not validate the present simplified equations. Crown fire, ember spotting, suppression and building combustion are absent.

The grid is row-major west-east, south-north; cell size supplies metric edge distance. Coordinate lookup uses the grid geographic bounds and wraps antimeridian longitude. Sensor distances use a local spherical tangent approximation. This remains a bounded-area approximation: high-latitude projection distortion requires further comparison against the declared projection; no worldwide accuracy is claimed. Sixteen-neighbour residual angular bias remains. Spatial refinement evidence now compares 50/25/12.5 m grids at common physical points: the 200 m east /100 m north target matches Euclidean arrival exactly; the 300/100 m target retains 2.333% directional error across all three resolutions. This exposes residual anisotropy rather than falsely claiming arbitrary-landscape continuum convergence. See packages/simulation/convergence-results.json.

## Sensor observation model

Every five simulation seconds, enabled sensors move exponentially toward weather/fire targets with the profile's time constant. Thermal distance is to active cells, approximated as cell footprints, rather than to the original ignition. Within the response radius, squared proximity scales temperature gain. Humidity uses a constant-vapour-pressure saturation ratio approximation. Smoke combines local response and finite-speed downwind transport with crosswind Gaussian diffusion and exponential decay. This is a test response model, not calibrated air pollution dispersion.

Seeded hash draws supply persistent bias and temporally correlated noise. Published measurements are restricted to each sensor's capabilities; absent channels stay absent, zero remains zero, and saturation is flagged. Sensor.simulationFaults now accepts deterministic half-open time windows for dropout, stuck value, additive spike, observation delay and smoke without fire. Optional channel masks apply only to supported capabilities. Dropout emits absent values with missing quality, stuck zero remains zero, known stuck/spike injections carry fault quality, and smoke without fire remains genuine non-fire smoke evidence. Delay windows apply at source observation time. Each five-second sample is assigned exactly one receipt tick, rounded forward from sampleTime + maximum active delay. The immutable scheduling rule acts as a replayable queue: packets are not emitted early, and delayed backlog is still delivered after the fault window ends. Measurement faults also apply at source time. A frame can contain multiple readings for one sensor; newest observed time is first, older due backlog follows, and each retains its stable source-time ID and recordedAt with delivery-tick receivedAt/late quality. Source time and delivery time must have separate persistence columns; a unique delivery-time key would lose coincident packets. Checkpoint replay, queue boundaries, overlapping delays and fractional-tick rounding are tested.

The engine caches at most four input identities. A checkpoint includes version, immutable input hash, arrival array and full sensor response/noise state, with a SHA-256 checksum. Infinite arrivals serialize as null. Restore rejects mismatched inputs and corruption. Seek starts from the nearest saved sensor state, repeats fixed steps and returns a whole frame. Frame readings use deterministic simulation receipt timestamps; persistence can record actual processing times separately. Playback speed and basemap style are absent from numerical inputs. Output requests are floored to the five-second sample clock.

## Inference boundary

predictFireSpread accepts observations, weather/landscape, satellite detections and previous posterior only. It has no ground-truth raster, scenario or ignition-list input. It initializes multiple burnable candidate locations/times using thermal proximity, upwind smoke hypotheses and a broad prior; retains a no-fire hypothesis; propagates each using the same transparent arrival solver; and robustly weights partial-channel likelihoods at observation time. Received-after-issue observations are excluded in operational mode. Fault/stale/missing observations are not treated as healthy negative evidence. IDs are deduplicated and same-device/collocated reports are downweighted.

The present likelihood is an approximate arrival/transport response, not the full synthetic sensor model. Consecutive anomaly counts and temperature/smoke rate-of-rise now persist in posterior sensorMemory across worker calls. Duplicate IDs do not change that memory or weights. Low conditional effective sample size triggers seeded systematic resampling and bounded burnable-cell/ignition-time rejuvenation, followed by recomputation of hypothesis arrivals. Calibrated likelihoods, learned bias, advanced long-history features and independent localization validation remain incomplete. A posterior weight floor prevents false certainty. Outputs distinguish currently burning, reached by time and origin mass; unknown cells remain null. Conditional arrival quantiles are seconds relative to issue time and include no-arrival probability. Satellite evidence is coarse and cannot create exact fire perimeters. Daily ML never silently modifies the minute-scale grid.

## Actual prepared-landscape performance correction (engine1.1.2)

The original single-weather synthetic benchmark did not expose a major variable-weather cost: the actual prepared Glendalough40,000-cell scenario could spend over two minutes in first-arrival computation. Each low-rate edge repeatedly integrated five-second steps toward the full six-hour horizon.

The corrected solver factors empirical edge rate into static terrain/fuel terms and reusable directional weather/moisture curves. At most128 curve tables are retained per solver; each includes every weather knot and the fixed numerical sample times. Prefix distance integrals make unreachable edges immediately detectable and arrival inversion logarithmic in time samples. Harmonic intervening fuel, slope, wind cap, moisture cap, rate cap and barrier geometry are retained. Tables do not depend on playback or wall clock. Published nonlinear fuel kernels and highly heterogeneous shapes beyond the bounded cache fall back to the reference integrator; their worst-case runtime remains a profiling limitation. The finer numerical solver changes arrival values slightly, so1.1.1 checkpoints are incompatible and existing completed scenarios require a new revision/run.

Executed prepared-data benchmark uses environment glendalough-9b9d9c7ba15f, acquired200×200 terrain, its two changing weather samples, four sensors and the full21,600-second horizon. Initial full frame completed in about0.79 seconds. Full-grid five-second versus2.5-second rate sampling agreed within0.0000012 seconds across19,339 reached cells with zero coverage differences. On an actual20×20 cropped landscape, the old fine-five-second solver took2.36 seconds versus0.068 seconds optimized; maximum arrival difference was0.000118 seconds across392 reached cells, with zero coverage differences. The full original40,000-cell old solver was not allowed to finish, so no invented full before/after speed ratio is claimed. Exact rerun measurements are retained in packages/simulation/prepared-benchmark-results.json.

17/17 simulation tests passed, including new convergence tests across off-grid weather knots, wind wrapping, precipitation/moisture caps, saturated spread rates, slopes and water barriers. These numerical comparisons establish engineering equivalence within the recorded tolerances, not scientific forecast calibration.

## surface-grid1.2.0: explicit linear downwind response
The user clarified on14November2026 that downwind spread should increase linearly with wind speed. For an edge aligned with the wind vector, the multiplier is1+0.35*c*u, where u is the along-edge wind component in m/s and c is the existing canopy adjustment (0.25woodland,0.4open fuels). For negative along-edge components, backing is damped by1/(1-0.35*c*u). Crosswind receives factor1. The final existing8m/s surface rate safety ceiling remains; very extreme speeds therefore saturate. This is a transparent simulator assumption, not a calibrated universal fire law.

The reference and optimized solvers use the same multiplier. Eight cardinal/diagonal propagation tests, single/multiple-weather equivalence, linear-increment rate tests, positive backing, water-barrier and replay tests pass. Slope, fuel and moisture remain independent influences, so the longest geographic extension need not always be exactly downwind on heterogeneous hills. UI fixes the map north-up and labels both wind-from and wind-to.

Model version changes invalidate old numerical outputs. Sandbox retains old objects, frozen environment and chosen horizon but resets generated frontier/cursor and creates a draft revision with a visible rerun notice. New local exports include engineVersion. This is a disclosed model migration, not silent deterministic compatibility.
