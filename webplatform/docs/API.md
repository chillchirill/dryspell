# HTTP, telemetry and worker API

HTTP and WebSocket share port 4000. All API responses are JSON. Errors have `{error:{code,message,details?,retryable?}}`. Contract revision 1.1.0. The domain wire contract is `packages/contracts/src/index.ts`; the coordinator maintains `docs/openapi.yaml`.

## Startup

Configure `DATABASE_URL` for actual PostgreSQL/PostGIS and `ADMIN_CONFIG_PATH` for a private CommonJS file exporting `{username,passwordSalt,passwordHash}`. The hash is 64-byte Node scrypt encoded as hexadecimal. `SESSION_SECURE=true` requires HTTPS; leave it false only for local HTTP testing. Run migrations, seed the retained landscape, start web and worker separately. No in-memory persistence substitute exists.

## Sessions and permissions

`POST /api/v1/auth/login` accepts `{username,password}` and returns `{authenticated,username,csrfToken}` with an HttpOnly SameSite=Strict session cookie. Mutations require that cookie and `X-CSRF-Token`; cross-origin requests are rejected. `GET /auth/session` restores session state. `POST /auth/logout` invalidates the database session. Anonymous users can read simulation, real readings, history and public diagnostics; they cannot change persisted objects. The WebSocket is read-only.

## Sensors and telemetry

GET/POST `/sensors`; GET/PATCH/DELETE `/sensors/:id`. Real creation requires `deviceId`, `name`, `location:{longitude,latitude}` and a profile; capabilities may be explicitly declared. Locations are effective-dated and existing observations retain their location version. `GET /sensors?at=ISO&archived=true` returns effective historical locations. PATCH supports archived/enabled to restore a sensor. DELETE archives by default; permanent deletion requires `?permanent=true` and `{confirmDeviceId,affectedRecords}` matching the affected telemetry count.

`POST /sensors/:id/credentials` issues `{id,token,deviceId}` once. Store the token securely; only its SHA-256 hash is persisted. `POST /credentials` accepts `{sensorIds:[...]}` to issue a gateway token for an explicit registered-device allowlist. `DELETE /credentials/:id` revokes it. Devices use `Authorization: Bearer TOKEN` with `POST /telemetry`:

```json
{"deviceId":"sensor-001","messageId":"boot-a7:1842","recordedAt":"2026-11-14T12:00:00Z","temperatureC":24.6,"humidityPct":61.2,"smokePct":0,"smoke":false}
```

Only registered, enabled, real sensors and declared capabilities are accepted. Smoke boolean is independent of numerical index. Omitted channels remain absent; zero remains zero. Missing recordedAt uses server time with a quality flag. Sensors can declare hardware.model and hardware.temperatureRangeC {min,max}. Ingestion enforces that registered range (default −100 to 1000 °C), within absolute accepted limits −273.15 to 5000 °C. Timestamp skew is limited to five future minutes and the raw retention window for old observations. Metadata depth is at most four and JSON packets are bounded to 128 KiB. Device credentials cannot move sensors or select simulation source.

Success is returned only after telemetry, latest state, analysis job and outbox commit. A repeated `(sensor,messageId)` returns duplicate; without messageId there is no deduplication guarantee. `POST /telemetry/batch` accepts `{readings:[...]}` with 1–100 items and per-item results. Late packets do not replace a newer latest value. `GET /sensors/:id/readings?from=ISO&to=ISO&cursor=ID&limit=N` returns a bounded array; `order=desc` returns the newest bounded window with matching descending keyset cursor semantics. `resolution=hour` returns min/max/count/mean aggregates. When from is omitted it defaults to to minus 24 hours. Historical observation availability is bounded by receivedAt≤to. `GET /readings/latest?at=ISO` is similarly availability-aware; `retrospective=true` explicitly permits hindsight.

## Scenarios

GET/POST `/scenarios`, GET/PATCH `/scenarios/:id`. Lists and objects are returned bare. Creation accepts validated name, seed, startTime, environmentId, sensors, ignitions and partial config; omitted fields use prepared defaults. Initial inputs remain revision1. Creation and editing both reject water ignition, unknown terrain, invalid profiles/configuration and invalid time zones. Output sampling remains fixed at5 seconds. PATCH requires `revision` or `expectedRevision`; stale edits fail with 409. Any accepted input change creates a draft revision at time zero while preserving previous frames. Scenario sensors are simulated profile objects. Their optional simulationFaults configure validated dropout, stuck, spike, delay and smoke-without-fire windows. Faults are rejected on real devices. Water/non-burnable and unknown-terrain ignition are rejected with recoverable messages. POST actions `/run`, `/pause`, `/stop`, `/clone` return the resulting Scenario. Run queues the worker; replay seek never changes authoritative time.

GET `/scenarios/:id/workspace` atomically returns `{scenario,environment,frame,cursor}`. GET `/state?at=SECONDS&revision=N` returns the latest recorded complete frame at or before the requested time. No recorded frame gives 404 FRAME_NOT_READY; the first worker step persists time zero. GET `/readings?sensorId=ID&to=SECONDS&revision=N` returns scenario observations. GET `/prediction?at=SECONDS&revision=N` returns an exactly matching PredictionResult or null. POST `/predictions` preferably accepts `{scenarioId,revision,at}`; the server constructs observation-only inference input and queues work. Full bounded PredictionInput is also supported on this route only with a 24 MiB body limit. Poll `/predictions/:id` for status/result. The UI must use revision/time matching, never an arbitrary last prediction.

## Delivery and jobs

`/ws?context=simulation&scenarioId=ID&cursor=N` sends typed envelopes. A fresh connection gets a consistent snapshot/cursor boundary. Reconnect resumes durable outbox events or requests resynchronization. Event insertion holds a transaction-scoped advisory lock before sequence allocation, ensuring commit order cannot skip a lower cursor. Ping/pong, bounded send buffers and slow-client reconnect are implemented. Live/history and simulation contexts are filtered independently; optional `devices=id,id` narrows notifications only. Bounded `bounds=west,south,east,north` (or area) filters live/history sensor events, supports the date line, and refreshes snapshot membership on reconnect. Simulation frames remain whole matching frames rather than being spatially cropped.

Workers claim jobs using `FOR UPDATE SKIP LOCKED`, leases, bounded retries and revision checks. Simulation frames/checkpoints are gzip-compressed bytea rows; sensor observations are unique by scenario/revision/sensor/time. Simulation inference runs as separate jobs. GET `/jobs/:id` exposes status, attempts and error. `/health/ready` reports actual database readiness separately from worker heartbeat and provider availability. The health endpoint does not claim all providers are healthy.

Incidents are separate from device health. Critical temperature at 70 °C is an alarm, not proof of wildfire. GET `/incidents?context=simulation&scenarioId=ID`; administrator POST `/incidents/:id/acknowledge` or `/confirm` records explicit actions. The alarm path requires three consecutive trustworthy warning observations and five complete recovery observations below lower hysteresis thresholds; 70 °C remains an immediate critical alarm. A temperature rise of at least 2 °C/min above 35 °C contributes warning evidence. Missing, faulty, stale or late readings cannot clear an alarm; missing channels that caused the alarm also prevent clearance. These are configurable engineering thresholds, not scientific calibration. Duplicate/out-of-order observations do not replay current alarm transitions.

Real telemetry analysis only runs when a covering immutable environmental snapshot contains real, time-valid weather; missing coverage emits an explicit unavailable source status. An administrator weather import with environmentId creates a new weather-refreshed snapshot for that area. Synthetic sample weather is never used to claim live forecasts.

## Health, satellite history and daily inference

GET `/sensors/status?at=ISO` returns SensorStatus objects. Connection state uses receipt time: stale after three expected intervals and offline after ten; observation freshness is separate and uses recordedAt. Waiting/disabled/archived are explicit states. The worker checks every ten seconds and emits `sensor.status` only when state/freshness changes. Device disconnection never clears fire evidence.

GET `/satellite?from=ISO&to=ISO&bounds=west,south,east,north&availableAt=ISO` returns at most 5000 persisted satellite observations. The availability cutoff defaults to to and filters receivedAt, so later ingestions cannot appear in operational history. An explicit later availableAt is a retrospective query. Points retain their instrument, nominal resolution and confidence class; they are never exact perimeters or probabilities.

POST `/predictions/daily` requires administrator authorization and accepts `{region,resolutionM,horizonHours,features,physicalProbabilities?}`. At most 4096 cells are accepted, with 13 features by default or the configured model manifest feature count. All numbers must be finite, physical probabilities must be 0–1 and match cell count, and arbitrary client model-directory paths are rejected. The worker alone loads `DRYSPELL_MODEL_DIR`. GET `/predictions/:id` returns the persisted daily result, explicit target scale/horizon and fallback reason. No configured/promoted model yields null probabilities unless a matching supplied physical baseline is available. Provider-to-daily-feature assembly and a promoted real-data model remain explicit prerequisites; no features are fabricated.

Worker polling delays apply only while idle or deliberately pacing simulation steps. Real jobs drain without a fixed 250 ms penalty. One queued observation-analysis cutoff per sensor is coalesced; a running job may have a newer queued successor. Raw observations remain durable and are read for subsequent inference. Simulation reading identity is observation ID, while time_sec is delivery time; multiple delayed observations may arrive in one tick. RecordedAt retains original observation time. Old-engine frames remain replayable, but Run rejects an engine-version change with 409 until the scenario is edited/cloned to a new revision.

The PostgreSQL pool handles idle-client errors without terminating the process; failed clients are replaced on later queries. Readiness degrades while actual queries fail and recovers when PostgreSQL accepts them again. Failed transaction rollback discards a broken connection while preserving the original operation error.

The single analysis worker holds a dedicated PostgreSQL session advisory lock for its lifetime. A replacement worker only resets abandoned running jobs after acquiring that exclusive lock, allowing immediate hard-crash recovery without waiting ten minutes. A second worker fails startup. Losing the lock connection stops job claiming and exits unsuccessfully so systemd can restart and reacquire ownership. Stop an older pre-lock worker during rollout before starting this version.
